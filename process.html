过程实现

从 Kaggle 搜索、下载、本地处理到生成说明文档与网页展示的完整链路

处理流程 五步流水线

分步详解 每步的目标 / 输入 / 工具 / 输出 / 产物

1

搜索 Kaggle

目标
按关键词定位公开数据集，沉淀候选列表（含 slug）。
输入
关键词 / 类别名称。
工具
search_kaggle_datasets.py
输出
候选数据集清单（owner/slug、标题、规模）。
产物
检索结果 JSON，作为下载阶段的输入。
2

下载数据集

目标
把候选数据集落到本地 datasets/，优先小文件与缺失项。
输入
slug 列表 / small_datasets.json 预设清单。
工具
download_small_datasets.py、download_small_datasets_cli.py、search_and_download.py
输出
各数据集文件夹 + 原始数据文件（CSV/JSON 等）。
产物
datasets/* 实际数据（本地保留，不入库）。
3

本地处理

目标
校验完整性、规整目录结构、标记数据状态。
输入
下载后的数据集文件夹。
工具
download_missing_datasets.py（补全）、test_kaggle_auth.py（凭证校验）
输出
状态标记：有数据 / 仅文档 / 缺失（NO_DATA_*）。
产物
数据集总览.txt、完成情况.txt。
4

生成说明

目标
批量为每个数据集生成中文介绍文档。
输入
数据集字段定义与样本数据。
工具
bulk_create_dataset_txts.py、create_remaining_txts.py
输出
每个文件夹的「数据集介绍.txt + README.md」。
产物
26 套双文档，构成说明文档体系。
5

网页展示

目标
把元数据与说明固化为可浏览静态站点。
输入
说明文档 + 统计指标 + 来源校验结果。
工具
手写静态页（index/process/roadmap/versions）+ style.css。
输出
四页互通的轻量站点（本页即其中之一）。
产物
web/ 站点，可离线打开或部署。

Kaggle 来源校验 新增 · 确保 slug 有效、授权可追溯

做什么
用 Kaggle API 逐个校验各数据集 slug 是否存在，并抓取许可证（license）、下载量、可用性评分等公开元数据。
脚本
verify_datasets_meta.py（遍历 24 个 ref，含失败重试退避）。
产物
datasets/datasets_meta.json —— 因 datasets/ 已被 .gitignore 排除，仅本地留存，不入库。
价值
① 验证页面中的 slug 真实有效；② 标注各数据集授权类型（如 CC0、CC BY），避免误用受限数据；③ 为后续详情页提供可溯源的来源链接。
安全
脚本仅读取项目本地 .kaggle/kaggle.json，绝不输出密钥；抓取到的元数据均为 Kaggle 公开信息，可安全展示。
