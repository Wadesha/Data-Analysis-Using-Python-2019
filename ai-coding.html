Prompt 工程模式 AI 交互的核心技能

模式复杂度原理 / 适用场景示例触发词
Zero-shot低不给示例，直接描述任务。简单任务有效（翻译 / 摘要 / 分类）"将以下英文翻译成中文：..."
Few-shot低给 2-5 个示例，隐式教模型输出格式和风格"示例：输入X→输出Y。现在处理：Z"
Chain-of-Thought中要求模型逐步推理，提高复杂推理准确率（数学 / 逻辑）"一步步思考，然后给出答案"
Self-Consistency高多次采样 CoT 推理路径，投票取多数，降低单次推理偏差多次调用 + 结果聚合
RAG中检索增强生成：先检索知识库，再让模型基于检索结果回答"基于以下文档回答：..."
Function Calling中模型输出结构化函数调用，实现 Tool Use / API 调用JSON Schema 定义工具
ReAct高Reason + Act 循环：思考→行动→观察→再思考，Agent 核心范式"Thought: ... Action: ... Observation: ..."
Reflection中模型自我审查输出，发现问题并修正，提升质量"检查你的回答是否有错误，如有则修正"
Tree of Thoughts高树状探索多条推理路径，回溯剪枝，适合搜索 / 规划问题多分支探索 + 评估剪枝
Structured Output低用 JSON Schema / Pydantic 约束输出格式，确保可解析"以 JSON 格式输出，包含字段：name, age"

AI 原生开发实践 vibecoding 时代的工作方式

📝 规格驱动开发

先写 PRD / Spec 文档（人类），再让 AI 逐段实现。Spec 即"源码"，代码是"编译产物"。工具：spec-kit / GitHub Issues → AI PR。

🔍 代码审查自动化

AI 审查 AI 生成的代码：安全漏洞 / 性能问题 / 最佳实践偏离。工具：CodeRabbit / Bito / Snyk Code。

🧪 AI 测试生成

AI 根据代码自动生成单元测试 / 集成测试 / E2E 测试。工具：Codium / Diffblue / Mabl。

📊 Eval 框架

评估 AI 应用质量：准确率 / 幻觉率 / 延迟 / 成本。工具：LangSmith / Phoenix / DeepEval / promptfoo。

🔧 AI-first 架构

从"AI 辅助编码"到"AI 原生架构"：Prompt 即配置 / 模型可替换 / 流式优先 / 降级策略 / 成本感知路由。

🔄 持续微调闭环

用户反馈 → 数据标注 → 模型微调 → 部署 → 监控 → 再收集。工具：Argilla / Label Studio / TRL + PEFT。

案例展示与解析 工具落地 + Prompt 实战

🔧 Cursor 重构遗留脚本 进阶

场景：一份 800 行的 Python 数据处理脚本，无测试、函数耦合，要拆成可维护模块。

选型：Cursor Composer 多文件编辑 + 代码库索引（@Codebase 引用上下文）。

步骤：① 让 Cursor 生成模块拆分方案 ② Composer 批量改写并在多文件间保持一致 ③ 让它补单元测试 ④ 人工审关键逻辑。

解析：Composer 比单文件补全强在「跨文件一致性」；但拆分类名/接口必须人工确认，避免 AI 改一半留悬空引用。最佳实践「代码审查」在此关键。

🧪 Copilot 单测生成 入门

场景：给已有业务函数补单元测试，覆盖边界与异常。

选型：GitHub Copilot 行内补全 + Chat 生成测试骨架。

步骤：① 注释写「为该函数写 pytest，覆盖空输入/越界/正常」② Copilot 生成用例 ③ 跑测试补缺失分支 ④ 接 CI 防回归。

解析：测试是最适合 AI 生成的低风险任务（有断言可验证）；但要审它是否「测了假东西」——断言恒为真的测试等于没测。

🚀 Claude Code 写 CI/CD 进阶

场景：从零配 Dockerfile + GitHub Actions 流水线，团队无 DevOps。

选型：Claude Code(CLI，能读写文件、跑命令、查 Git)。

步骤：① 让它读项目生成多阶段 Dockerfile ② 写 .github/workflows/ci.yml(测试+构建+镜像推送) ③ 本地跑 actions 验证 ④ 提交。

解析：CLI 型工具适合「能执行命令」的任务；但密钥/权限类配置必须人工复核，别让它把 secrets 写死进文件（见 密钥安全）。

🎯 Prompt：RAG + Reflection 实战 进阶

场景：让模型基于检索文档回答，且减少编造。

选型：RAG(检索增强) + Reflection(自我审查) 两段式 Prompt。

步骤：① 拼「仅用以下片段回答，超出则说不知道」② 拿到初稿后加「检查引用是否准确、有无臆测」再修正 ③ 输出带出处。

解析：单轮 RAG 仍可能幻觉；Reflection 让模型二次核对来源，幻觉率明显下降。智能体「Reflection 范式」即此模式的工程化。
