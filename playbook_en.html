🎯 Playbook: Cases & Best Practices

From "can describe requirements" to "can ship projects" · 6 beginner-friendly cases + 7 reusable vibecoding principles

How to use this page: the beginner cases give you the shortest "follow along" path — each case lists its tech stack, time cost, and reusable hub resources; the best practices are a checklist you should revisit every time you start a new project. Together they help you avoid the two classic failures: "AI generated it but it won't run" and "leaked on launch".

Beginner Cases zero experience · shippable in 30 min – 2 hrs

🌟 Personal Portfolio / Blog ~30 min

Goal: Generate a responsive personal site with AI and deploy it to the public web.

Stack: Next.js (App Router) · Tailwind · Vercel · Cursor

Steps: ① Use Cursor to scaffold the Next.js skeleton → ② describe the layout and let AI fill in the components → ③ use an AI writing assistant to generate articles → ④ vercel --prod one-command deploy.

Reuses: Templates "Next.js template" · API "Vercel deployment"

📚 RAG Knowledge Base Q&A ~1 hr

Goal: Upload documents and ask questions in natural language to get document-grounded answers.

Stack: Python · LangChain · OpenAI/Claude · Vector DB (Qdrant/Pinecone) · Streamlit

Steps: ① Chunk documents + embed → ② build the retriever → ③ compose the "answer based on retrieved results" prompt → ④ stream the output → ⑤ add a UI.

Reuses: AI Coding "RAG pattern" · Models "LLM" · API "vector DB"

📊 Interactive Data Dashboard ~45 min

Goal: Turn a CSV into a filterable, interactive dashboard.

Stack: Python · pandas · Streamlit · this project's 13 local datasets

Steps: ① Load the dataset → ② let AI write chart functions (bars / distributions / missing rates) → ③ add filters and interactions → ④ deploy to Streamlit Cloud.

Reuses: Datasets Hub "13 local datasets with charts" · wine example

🔌 Chrome Extension (AI Summary) ~1 hr

Goal: Select text on any webpage and get a one-click LLM summary / translation.

Stack: Manifest V3 · JavaScript · LLM API (OpenAI/DeepSeek)

Steps: ① Write the manifest + a content script to capture the selection → ② call the LLM API → ③ show results in a popup UI → ④ load locally (chrome://extensions) to test.

Reuses: API "LLM" · Agents "Tool Use"

🤖 Automated Weekly Report Agent ~2 hrs

Goal: Automatically summarize this week's Git/Issue progress into a structured weekly report.

Stack: n8n / CrewAI · GitHub API · LLM

Steps: ① Connect the GitHub API to pull commits/PRs → ② design "analyst + writer" multi-role agents → ③ compose the report template → ④ schedule the trigger (every Friday).

Reuses: Agents "CrewAI / multi-agent" · API "GitHub"

💬 Telegram / Slack Bot ~1 hr

Goal: Use natural language to make a bot query data / call APIs / send notifications.

Stack: Python · python-telegram-bot · LLM · any backend API

Steps: ① Create a bot via @BotFather and get the token → ② write the message handler → ③ connect an LLM for intent understanding → ④ deploy on Railway (free tier).

Reuses: API "Telegram / Slack" · Models "LLM"

Intermediate Cases tackle after the basics · 2–4 hrs

🎯 Fine-tune Your Own Support Model Intermediate

Goal: Generic LLMs can't handle your business terminology — customize a small model with domain data.

Stack: Python · PEFT · TRL · Unsloth · DeepEval · one of this project's 13 datasets as training samples

Steps: ① Prepare Q&A-pair SFT data → ② Unsloth + LoRA single-GPU training → ③ DeepEval evaluation against the baseline → ④ export and wire up inference.

Reuses: Templates · fine-tuning case · Models · fine-tuning toolchain · Datasets Hub

🎨 Multimodal Content Generation Pipeline Intermediate

Goal: Feed in an article and automatically produce illustrations + voice narration + a short video.

Stack: GPT-4o Vision · SD/FLUX · OpenAI TTS · ffmpeg

Steps: ① An LLM splits the script and writes scene descriptions → ② text-to-image (local ComfyUI to save money) → ③ TTS voiceover → ④ ffmpeg composes the video.

Reuses: Models · multimodal case · API · transcription case

🗂 Data Pipeline Automation Intermediate

Goal: Every day, automatically clean, join, and visualize multi-source CSVs into an interactive dashboard.

Stack: Python · Polars · DuckDB · Prefect · Streamlit · this project's local datasets

Steps: ① Prefect orchestrates the daily jobs → ② Polars cleans + DuckDB aggregates → ③ Streamlit renders → ④ Great Expectations alerts on anomalies.

Best Practices a checklist to revisit every time you start a new project

📋 Spec-driven (Spec-first)

Write down "what to build" first (PRD / spec / user stories), then let AI implement it. Structured requirements significantly reduce AI hallucination and rework.

How: use GitHub Issues or spec-kit to break requirements into small verifiable items, and have AI deliver and self-check them one by one.

🎯 Prompt Engineering Principles

Stick to a stable five-part structure: "role + task + constraints + examples + output format"; break big tasks into small steps and verify incrementally — never dump a giant requirement on AI at once.

Advanced: structured output (JSON Schema), few-shot examples, Reflection self-checks. See AI Coding "Prompt patterns".

🔍 Code Review & Testing

AI-generated ≠ correct. Must-dos: ① manually review critical logic ② have AI add unit tests / E2E ③ wire AI review tools (CodeRabbit / Snyk Code) as a safety net.

This project runs the check_render.js regression gate on every page change — proof that "AI-written code needs testing too".

🔐 Secret & Credential Security (battle-tested in this project)

Credentials never enter code or the repo: store them in the macOS Keychain (security add-internet-password), exclude .env and *.token via .gitignore, and confirm before pushing.

Lesson: this project once pushed a GitHub token to a repo without protection and it leaked — since then we switched to Keychain + strict .gitignore protection.

💰 Cost Control

Use small models (Haiku / DeepSeek) for simple tasks and reserve big models for complex reasoning; add caching and batch calls, and monitor token usage to avoid hidden overspend.

Architect "cost-aware routing": automatically pick the model by task difficulty — see Model Hub "deployment options comparison".

🔄 Version Control & Deployment

Commit in small steps with clear commit messages; let CI run checks before merging; prefer serverless deployment (Vercel / Railway / Cloud Run) to reduce ops burden.

This project's static site can go straight to GitHub Pages, but every push-triggered deploy requires your confirmation to avoid quota burn and accidental exposure.

⚠️ Common Pitfall Avoidance

① Blindly trusting AI-output version numbers / API details (always verify) ② shipping without tests ③ committing large files / datasets / secrets to the repo ④ going public without sanitization.

This project's principle: no raw data in the repo (metadata + derived stats only), and visualizations use aggregated values only — avoiding size and copyright risks at the source.
