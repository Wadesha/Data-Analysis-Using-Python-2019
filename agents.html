Agent 关键组件 构建生产级 Agent 的基础设施

🧠 推理引擎

LLM 作为 Agent 大脑：GPT-4o / Claude 3.5 / Llama 3.1 / DeepSeek V3。选型维度：推理能力 / 工具调用 / 上下文长度 / 成本。

🔧 工具集成

Function Calling / MCP (Model Context Protocol) / 自定义 Tools。MCP 是 Anthropic 提出的通用工具协议，正在成为标准。

💾 记忆系统

短期：对话窗口 / Scratchpad。长期：向量数据库（Qdrant / pgvector）+ 知识图谱。工具：Mem0 / Zep / Letta。

📋 任务规划

任务分解（Task Decomposition）+ 依赖管理 + 状态追踪。工具：LangGraph State / CrewAI Tasks / AutoGen GroupChat。

👁 可观测性

Trace 每一步推理 / 工具调用 / Token 消耗。工具：LangSmith / Phoenix / Langfuse / Weave。

🛡 安全防护

Prompt Injection 防御 / 输出过滤 / 权限控制 / 审计日志。工具：Guardrails AI / NeMo Guardrails / Llama Guard。

案例展示与解析 框架选型 + 架构权衡

🎧 LangGraph 客服 Agent 进阶

场景：多轮客服，需要查订单、走退款流程、敏感操作人工介入。

选型：LangGraph(状态机 + 图编排)，因支持循环/分支/持久化与 Human-in-the-Loop。

步骤：① 定义 State(对话/上下文/工具结果) ② 节点：意图识别→工具调用→回答 ③ 退款等高风险节点加 interrupt_before 人工审批 ④ 用 Checkpointer 持久化。

解析：图结构比线性链更适合有「回退/分支」的业务流；持久化让对话可恢复。模板「Agent 应用」即此架构。

📝 CrewAI 自动周报 入门

场景：每周五汇总 Git/Issue 进展成结构化周报，发给团队。

选型：CrewAI(角色驱动多 Agent)，API 简洁，适合「研究员+写手」分工。

步骤：① Researcher Agent 拉 GitHub/Issue 数据 ② Writer Agent 据模板成文 ③ Crew 顺序执行 ④ 定时触发(Cron/n8n)。

解析：多角色把「收集」与「表达」解耦，输出更聚焦；比单 Agent 一步到位更可控。实战案例「周报 Agent」即此。

🔍 AutoGen 代码评审 进阶

场景：PR 提交后自动多视角审查（安全/性能/可读性）。

选型：AutoGen GroupChat，多 Agent 对话辩论，微软出品、可编程。

步骤：① 建 Reviewer/security/perf 三个 Agent ② GroupChat 轮流发言给意见 ③ 汇总成评审报告 ④ 接 GitHub Action 评论 PR。

解析：多 Agent 辩论能互相纠错，比单轮评审更全面；但 token 成本更高，适合关键 PR 而非每次提交。

🧭 架构解析：ReAct vs Plan-Execute 深度

选型逻辑：任务可一步工具解决 → Tool Use；需边想边搜 → ReAct；步骤多且可预判 → Plan-and-Execute。

步骤：① 评估任务不确定性 ② 低不确定用 Plan 先列全步骤再执行(省 token) ③ 高不确定用 ReAct 边走边调。

解析：Plan-Execute 在稳定任务上更省、更可预测；ReAct 在探索型任务(检索/调试)上更鲁棒。误用会浪费成本或失控——这是 AI 编码「成本感知」的延伸。
