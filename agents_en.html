Agent Design Paradigms Core patterns and applicable scenarios

ParadigmComplexityFlowUse cases
ReActMediumThought → Action → Observation → Thought → ... → AnswerGeneral-purpose agents / tool calls / information retrieval
Plan-and-ExecuteHighPlan the full step list first → execute step by step → adjust the plan based on resultsComplex tasks / multi-step workflows / project-level tasks
Tool UseLowThe model outputs a Function Call → execute the tool → feed the result back to the modelAPI calls / database queries / code execution
ReflectionMediumGenerate → self-evaluate → revise → regenerate, iterating to improve qualityCode generation / copywriting / quality-sensitive tasks
MemoryHighShort-term (conversation context) + long-term (vector store / knowledge graph) memory managementLong-running conversations / personal assistants / knowledge accumulation
Multi-AgentHighMultiple roles collaborating (e.g., PM / dev / QA), coordinated via message passingSoftware development / complex research / role-playing
Human-in-the-LoopMediumThe agent pauses at critical steps and waits for human approval before continuingHigh-risk operations / compliance review / user experience
Code AgentMediumThe model directly generates Python code as the action instead of a JSON Function CallData analysis / flexible tool composition / complex logic

Key Agent Components Infrastructure for production-grade agents

🧠 Reasoning Engine

The LLM as the agent's brain: GPT-4o / Claude 3.5 / Llama 3.1 / DeepSeek V3. Selection criteria: reasoning ability / tool calling / context length / cost.

🔧 Tool Integration

Function Calling / MCP (Model Context Protocol) / custom tools. MCP, a universal tool protocol proposed by Anthropic, is becoming the standard.

💾 Memory System

Short-term: conversation window / scratchpad. Long-term: vector databases (Qdrant / pgvector) + knowledge graphs. Tools: Mem0 / Zep / Letta.

📋 Task Planning

Task decomposition + dependency management + state tracking. Tools: LangGraph State / CrewAI Tasks / AutoGen GroupChat.

👁 Observability

Trace every reasoning step / tool call / token consumption. Tools: LangSmith / Phoenix / Langfuse / Weave.

🛡 Safety Guardrails

Prompt injection defense / output filtering / permission control / audit logs. Tools: Guardrails AI / NeMo Guardrails / Llama Guard.

Case Studies & Analysis Framework selection + architecture trade-offs

🎧 LangGraph customer-service agent Intermediate

Scenario: Multi-turn customer service that needs to look up orders, run refund workflows, and involve humans for sensitive operations.

Choice: LangGraph (state machine + graph orchestration), because it supports loops / branches / persistence and Human-in-the-Loop.

Steps: ① Define the State (conversation / context / tool results) ② Nodes: intent recognition → tool call → answer ③ Add interrupt_before for manual approval on high-risk nodes like refunds ④ Persist with a Checkpointer.

Analysis: Graph structures fit business flows with "rollback / branching" better than linear chains; persistence makes conversations resumable. The "Agent application" in Templates is exactly this architecture.

📝 Automated weekly reports with CrewAI Beginner

Scenario: Every Friday, aggregate Git/Issue progress into a structured weekly report and send it to the team.

Choice: CrewAI (role-driven multi-agent); its concise API fits a "researcher + writer" division of labor.

Steps: ① A Researcher agent pulls GitHub/Issue data ② A Writer agent drafts from a template ③ The Crew runs sequentially ④ Trigger on a schedule (Cron/n8n).

Analysis: Multiple roles decouple "collecting" from "expressing", making the output more focused and more controllable than a single agent doing everything in one shot. The "weekly report agent" in Playbook Cases is exactly this.

🔍 Code review with AutoGen Intermediate

Scenario: After a PR is submitted, automatically review it from multiple angles (security / performance / readability).

Choice: AutoGen GroupChat — multi-agent conversational debate; from Microsoft and programmable.

Steps: ① Create three agents: Reviewer / security / perf ② GroupChat takes turns giving feedback ③ Aggregate into a review report ④ Comment on the PR via a GitHub Action.

Analysis: Multi-agent debate lets agents correct each other and is more thorough than single-pass review; but the token cost is higher, so reserve it for critical PRs rather than every commit.

🧭 Architecture analysis: ReAct vs Plan-Execute Deep dive

Selection logic: If the task can be solved with one tool call → Tool Use; if it needs thinking while searching → ReAct; if it has many predictable steps → Plan-and-Execute.

Steps: ① Assess task uncertainty ② For low uncertainty, use Plan to list all steps first, then execute (saves tokens) ③ For high uncertainty, use ReAct to adjust as you go.

Analysis: Plan-Execute is cheaper and more predictable on stable tasks; ReAct is more robust on exploratory tasks (retrieval / debugging). Misuse wastes budget or spins out of control — an extension of "cost-awareness" in AI Coding.
