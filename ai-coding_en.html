Prompt Engineering Patterns The core skill of AI interaction

PatternComplexityPrinciple / use casesExample trigger
Zero-shotLowNo examples; describe the task directly. Effective for simple tasks (translation / summarization / classification)"Translate the following English into Chinese: ..."
Few-shotLowProvide 2-5 examples to implicitly teach the model the output format and style"Example: input X → output Y. Now process: Z"
Chain-of-ThoughtMediumAsk the model to reason step by step, improving accuracy on complex reasoning (math / logic)"Think step by step, then give the answer"
Self-ConsistencyHighSample multiple CoT reasoning paths and take a majority vote to reduce single-run biasMultiple calls + result aggregation
RAGMediumRetrieval-augmented generation: retrieve from a knowledge base first, then answer based on the retrieved content"Answer based on the following documents: ..."
Function CallingMediumThe model outputs structured function calls, enabling Tool Use / API invocationTools defined with JSON Schema
ReActHighReason + Act loop: think → act → observe → think again; the core agent paradigm"Thought: ... Action: ... Observation: ..."
ReflectionMediumThe model reviews its own output, finds problems and fixes them, improving quality"Check your answer for errors and fix them if any"
Tree of ThoughtsHighTree-structured exploration of multiple reasoning paths with backtracking and pruning; good for search / planning problemsMulti-branch exploration + evaluation and pruning
Structured OutputLowConstrain the output format with JSON Schema / Pydantic to ensure parseability"Output in JSON format with fields: name, age"

AI-Native Development Practices How we work in the vibecoding era

📝 Spec-Driven Development

Write the PRD / spec doc first (by humans), then have AI implement it section by section. The spec is the "source code"; the code is the "compiled artifact". Tools: spec-kit / GitHub Issues → AI PR.

🔍 Automated Code Review

AI reviews AI-generated code: security vulnerabilities / performance issues / deviations from best practices. Tools: CodeRabbit / Bito / Snyk Code.

🧪 AI Test Generation

AI automatically generates unit / integration / E2E tests from code. Tools: Codium / Diffblue / Mabl.

📊 Eval Frameworks

Evaluate AI application quality: accuracy / hallucination rate / latency / cost. Tools: LangSmith / Phoenix / DeepEval / promptfoo.

🔧 AI-First Architecture

From "AI-assisted coding" to "AI-native architecture": prompts as configuration / swappable models / streaming-first / fallback strategies / cost-aware routing.

🔄 Continuous Fine-Tuning Loop

User feedback → data labeling → model fine-tuning → deployment → monitoring → re-collection. Tools: Argilla / Label Studio / TRL + PEFT.

Case Studies & Analysis Tool adoption + prompt practice

🔧 Refactoring a legacy script with Cursor Intermediate

Scenario: An 800-line Python data-processing script with no tests and tightly coupled functions that needs to be split into maintainable modules.

Choice: Cursor — Composer multi-file editing + codebase indexing (@Codebase to reference context).

Steps: ① Have Cursor generate a module-splitting plan ② Use Composer to batch-rewrite while keeping the files consistent ③ Have it add unit tests ④ Manually review the key logic.

Analysis: Composer's edge over single-file completion is "cross-file consistency"; but the split's class names / interfaces must be confirmed by a human, or the AI may leave dangling references halfway. "Code review" in Best Practices is critical here.

🧪 Unit test generation with Copilot Beginner

Scenario: Add unit tests to existing business functions, covering boundaries and exceptions.

Choice: GitHub Copilot — inline completion + Chat to generate test skeletons.

Steps: ① Write a comment: "Write pytest for this function, covering empty input / out-of-range / normal cases" ② Copilot generates the cases ③ Run the tests and fill in missing branches ④ Wire into CI to prevent regressions.

Analysis: Testing is the best low-risk task for AI generation (assertions are verifiable); but review whether it "tested the wrong thing" — a test whose assertions always pass is as good as no test.

🚀 Writing CI/CD with Claude Code Intermediate

Scenario: Set up a Dockerfile + GitHub Actions pipeline from scratch; the team has no DevOps.

Choice: Claude Code (CLI; can read/write files, run commands, and inspect Git).

Steps: ① Have it read the project and generate a multi-stage Dockerfile ② Write .github/workflows/ci.yml (test + build + image push) ③ Verify the actions locally ④ Commit.

Analysis: CLI-type tools suit tasks that "can execute commands"; but secret/permission configs must be manually reviewed — don't let it hardcode secrets into files (see Secrets Security).

🎯 Prompt: RAG + Reflection in practice Intermediate

Scenario: Have the model answer based on retrieved documents while reducing fabrication.

Choice: RAG (retrieval-augmented) + Reflection (self-review) as a two-stage prompt.

Steps: ① Assemble "Answer using only the following excerpts; say you don't know beyond them" ② After the first draft, add "Check whether the citations are accurate and whether anything is assumed" and revise ③ Output with sources.

Analysis: Single-turn RAG can still hallucinate; Reflection makes the model double-check sources, noticeably lowering the hallucination rate. The "Reflection paradigm" in Agents is the engineering formalization of this pattern.
