案例展示与解析 真实选型决策与权衡

💬 客服问答机器人 入门

场景：电商站需要 7×24 自动回答物流 / 退换货问题，日均约 2 万次咨询，含订单查询等敏感操作。

选型：通用问题用 Claude Haiku（便宜、200K 上下文）承接 80%；涉及用户订单时切到 Ollama + Llama 3.1 本地部署，数据不出内网。

步骤：① 用 Claude 写 FAQ 抽取脚本 ② 接 Function Calling 查订单 API ③ 成本敏感走 Haiku、隐私问题走本地，做「成本感知路由」。

解析：闭源 API 延迟低但按 Token 计费，2 万次/日量级月成本可控；纯本地隐私最佳但需 GPU。混合路由兼顾两者——正是 AI 编码「成本感知路由」的落地。

📚 企业 RAG 知识库 进阶

场景：把 5 万份内部文档变成可问答的知识库，要求答案有出处、不胡编。

选型：BGE-large 本地 Embedding（数据不出域）+ Cohere Rerank 二阶段精排 + GPT-4o 生成；向量存 pgvector。

步骤：① 文档切块(512 token)→BGE 向量化入 pgvector ② 召回 Top-20→Cohere 重排取 Top-5 ③ 拼「仅基于下文回答」Prompt 让 GPT-4o 生成并附引用。

解析：单阶段向量检索召回率有限，加 Reranker 后答案相关性显著提升；Embedding 用本地模型既省钱又满足合规。API「Cohere」与 技术栈「pgvector」在此组合。

🖼 多模态内容审核 进阶

场景：UGC 平台需同时理解图文（用户配文 + 图片）判断是否违规，峰值 QPS 高。

选型：常规图文用 Gemini 2.0 Flash（便宜、1M 上下文、原生多模态）；疑难长图/视频帧用 GPT-4o 兜底。

步骤：① 图片+文本拼成一个多模态请求 ② 路由：短内容走 Gemini Flash、长上下文走 Gemini Pro、争议样本走 GPT-4o 人工复核队列。

解析：多模态模型原生支持图文混合输入，比「OCR+LLM」两段式更简单；用 部署方式对比 的思路做按难度路由，把贵模型留给难样本。

后续计划：模型对比基准（MMLU / HumanEval / MT-Bench）、按显存推荐模型表、微调工具链（LoRA / QLoRA / DPO）指南、模型量化方案对比（GGUF / AWQ / GPTQ）。本页「案例展示与解析」已于 v2.19 补充。
